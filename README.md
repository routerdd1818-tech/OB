# 對話之間 · CQ Dialogue Lab

跨文化課堂互動系統。學員 `/` 與簡報者 `/host` 分開呈現，以暖米色介面進行五組獨立決策、四回合覆盤與 CQ 健康度追蹤。

## 本機啟動

需要 Node.js 22.9 以上。不需要安裝套件。

```powershell
node server.mjs
```

- 學員：http://127.0.0.1:3000/
- 簡報者：http://127.0.0.1:3000/host
- 未設定環境變數時，本機簡報者密碼：`classroom-demo`。
- 使用自訂設定：複製 `.env.example` 為 `.env`，填寫後執行 `node --env-file=.env server.mjs`。本機不使用 Redis 時，刪除兩個 Upstash 範例值。
- 本機資料保存於 `.data/workshop.json`，重新啟動不會清除；用主控台「課堂管理 → 重設課堂」開始新課。
- 手機測試：手機與電腦連上同一 Wi-Fi，以電腦的區網 IPv4（例如 `http://192.168.1.20:3000/host`）開主控台。產生的 QR Code 就會指向該區網的學員網址。`localhost` 或 `127.0.0.1` 的 QR Code 無法讓另一台手機連到電腦。

## Vercel 部署

此專案包含部署設定，**尚未部署到正式網域**。本機可獨立運作；Vercel 上必須設定共用 Redis，不能依賴函式記憶體或檔案系統保存全班狀態。

1. 將此資料夾推送到自己的 Git 儲存庫，再從 Vercel 匯入。Framework Preset 選 **Other**，Node.js 選 22.x 或更新版本。
2. 建立 Upstash Redis 資料庫，設定以下 Vercel Environment Variables：

| 變數 | 用途 |
| --- | --- |
| `HOST_PASSWORD` | 自訂長密碼，只提供給簡報者；正式環境沒有預設密碼。 |
| `UPSTASH_REDIS_REST_URL` | Upstash HTTPS REST URL。 |
| `UPSTASH_REDIS_REST_TOKEN` | Upstash REST 寫入 Token，僅供伺服器使用。 |
| `WORKSHOP_KEY` | 課堂資料識別鍵，預設 `cq-dialogue-workshop`。每個獨立課堂／環境應不同。 |
| `PUBLIC_URL` | 建議填入正式學員首頁，例如 `https://your-project.vercel.app/`，固定 QR Code 指向。 |

3. Vercel 自動套用 `vercel.json`：Build Command 為 `node scripts/build.mjs`，Output Directory 為 `dist`；`/host` rewrite 到 `host.html`，API 位於 `/api/workshop`。
4. 部署後先以簡報者登入，再用至少兩台手機測試不同組別。Preview 與 Production 使用不同 `WORKSHOP_KEY`，避免測試改動正式課堂。
5. 讓學員可存取正式網域；若帳戶啟用了部署保護，依教室使用範圍調整。不要把簡報者密碼放入網址或 QR Code。

技術依據：[Vercel 路由設定](https://vercel.com/docs/routing/rewrites)、[Upstash REST API](https://upstash.com/docs/redis/features/restapi)。

## 課堂操作

1. 簡報者開 `/host` 登入，點「掃碼加入」。學員填姓名並選 1–5 組，無組別人數建議或上限。
2. 每組首位加入者自動成為代表。所有組員都能看到題目、方案與本組已提交決策；只有代表能提交。簡報者可在課堂管理更換代表。
3. 點「開始本回合研討」。前三回合為 3 分鐘；可暫停與繼續。歸零僅提示時間到，由簡報者按揭曉結束投票，保留現場討論彈性。
4. 投影只顯示情境、對話、全班完成組數與 CQ。各組提交內容不傳送至其他組；開票前主控台 API 也不回傳選項或各組選擇。
5. 揭曉一次後鎖票、計算各組 CQ，展示全班分佈、平均張力與方案覆盤。未提交組別不扣分，也不納入張力平均。再次開票不會重複計分。
6. 點下一回合後，需要再按「開始本回合研討」，讓簡報者有時間讀情境。
7. 第四回完成後可結束課堂。重設需確認，會清除名單、所有決策與分數，所有學員重新加入。

### 第四回：每組內部三方協商

五組各自完成同一個情境，組內扮演「總部、東京、客戶」三方；人數不限，必要時一人兼任角色。代表記錄實際討論結果，系統不宣稱已分別驗證三方身分。

| 時段 | 任務 |
| --- | --- |
| 60–41 秒 | 交換立場：各方說明最關心的風險與需求。 |
| 40–21 秒 | 協商提案：對照四種方案，討論可共同接受的安排。 |
| 20–0 秒 | 三方表態：代表逐項記錄同意或拒絕，再提交。 |

三方全部同意，套用所選 A–D 結果；任一方拒絕，套用破局結果（張力 100%、CQ −25）。不能省略任一方的表態。

## CQ 計分設計

CQ 在此是**課堂合作健康度**，不是對個人能力的心理測量。每組初始 100，範圍 0–100；回復分數用來鼓勵修復，最高維持 100。數值只在揭曉後改變，呈現實際增減值；滿分組選擇修復方案仍為 100，顯示守住健康度。

| 回合 | A | B | C | D | 破局 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 認知 | −15 | −20 | −10 | +10 | — |
| 2 動機 | −15 | −10 | −25 | +10 | — |
| 3 行為 | −20 | −15 | −10 | +10 | — |
| 4 巔峰博弈 | −10 | −15 | −10 | +15 | −25 |

- −10：有限緩解但核心需求仍未獲滿足。
- −15：信任或尊嚴持續受損。
- −20：接管／監控造成更強的防衛與失去自主感。
- −25：造成合作破局或重大次生危機。
- +10 / +15：恢復心理安全、專業尊嚴與合作；第四回的三方共識回復 15。

CQ 不是張力差值的線性換算。題庫、張力矩陣與 CQ 可在 `lib/rounds.mjs` 集中調整；`neutralTitles` 是開票前的中性選項名稱。原題所提供的張力百分比全部保留。

### 張力計算

顯示「起始張力 − 決策後張力」的**百分點**差，例如 85% → 35% 顯示降低 50 個百分點，避免誤寫成相對降幅。第一至四回起始值為 85、90、95、98%。

全班 Hero 採已提交組別之決策後張力算術平均，保留一位小數；同時展示各組分佈，避免把平均值當成單一組別的結果。學員只看見本組結果。所有數值是教學情境模型，不代表實測心理數據；文化脈絡不等於每個個人的固定特徵。

## 資料與保密機制

- 伺服器產生隨機 session，HttpOnly + SameSite=Strict cookie；正式環境加上 Secure。身份與組別從伺服器 session 決定，忽略客戶端偽造的組別。
- 學員 API 只序列化本組資料；不以 CSS 隱藏其他組資料。題庫答案只在伺服器，沒有放進 `public` 或 `dist`。
- 自選組別適用受控教室；它不是實名驗證。若要防止同一人用不同瀏覽器重新報名，需另增個人邀請碼或學校登入。
- 正式環境使用 Redis Lua revision compare-and-set，防止同時投票互相覆蓋；本機採序列更新與檔案原子替換，限單一 Node 程序。
- 每 1.5 秒更新，背景分頁降為每 5 秒；時鐘以伺服器時間校正。斷線顯示提示並停用提交，恢復後保留本輪未送出選擇；過期回合與重設前的決策被拒絕。
- 姓名與組別只保存於課堂資料庫，沒有第三方分析追蹤。QR Code 使用本地套件，不把加入網址傳給外部 QR 圖片服務。
- session 12 小時到期；資料不自動刪除，簡報者於課後重設清除。正式使用應管理資料庫存取與備份保留期限。
- 題目／回合目前為每個 `WORKSHOP_KEY` 一堂課；不同班級同時進行請用不同部署或識別鍵。

## 驗證

```powershell
node --test test/*.test.mjs
node scripts/build.mjs
```

整合測試以暫存資料與獨立 HTTP 伺服器驗證：登入、五組同時投票與隔離、代表權限、揭曉一次計分、舊回合拒絕、計時暫停／繼續、未全數提交保護、第四回共識、代表更換、重設、張力矩陣、靜態資源無答案、來源檢查與登入限速。測試不改動本機預覽的課堂資料。

已於內建瀏覽器檢查桌面投影版與 390px 手機版；真實 iPhone Safari、正式 Vercel 與真實 Upstash 環境仍需部署後驗收。
